# Guardian (Android) — work in progress

Guardian will block tracker domains on the phone itself, using Android's VpnService as a local DNS filter. No remote server is involved, and none is planned. It is a separate app from Permission Checkup (`android/permcheck`), which keeps its promise of no INTERNET permission.

Licensed GPL-3.0-or-later.

| CNAME uncloaking (G14) | Claude wrote this. Trackers hide behind a first-party subdomain whose CNAME points at the tracker; the query name is on no list. `DnsAnswer.cnameTargets` reads the CNAME chain of each upstream answer (compression pointers, bounds-checked, at most 16 jumps and 64 records, anything malformed is forwarded unchanged). If a target is blocked, Guardian returns its usual blocked answer and the log line reads "metrics.shop.example → really shop.tracker.example". Your allow on the query name or on the target wins; nothing is uncloaked while paused. `CnameTest` (11 groups, including 20,000 random messages and every truncation) passes; a mutation that disables the check fails it. These blocks count in the daily history but not in "Blocked most often", whose rule line is computed from the query name. |

| Blocking strength (G13) | DeepSeek wrote to Claude's spec, after TrackerControl's Minimal/Standard/Strict. | Broad Exodus patterns get no company name (G15b) | Claude wrote this. Some Exodus rows only say "any subdomain of one domain" (`\.google\.com` is filed under Google Ads, seven Facebook rows use `\.facebook\.com`); most names there are the company's own services, so labelling them would mislead. A row whose every pattern has the form `\.<label>\.<tld>` is marked broad and is never used to name a blocked domain (its code signatures still serve G17). With the bundled data that is 14 rows: the 8 Google/Facebook ones, and 6 trackers' own domains (ChartBoost, Dynatrace, DOV-E, Glympse, Lenddo, Cifrasoft) that lose a label which was correct; no domain gets a wrong label. `TrackerDbTest` (15 groups: mail.google.com and graph.facebook.com get no label, doubleclick.net is still Google DoubleClick) passes; three mutations each fail it. |
| Stalkerware server alerts (G20) | Claude wrote this. Bundled list of 993 stalkerware command-and-control domains from Echap's stalkerware-indicators (CC-BY 4.0, credited in the app; `tools/update_stalkerware.py` pins the source commit). Only C2 domains are used, not vendors' marketing websites; 128 domains that are both are worded "website or servers" with "if you were only reading about it, ignore this". When a lookup matches a listed domain or its subdomain, Guardian posts a notification whose lock-screen version says only "Guardian has a safety alert". It alerts but never blocks, so whoever installed the stalkerware is not tipped off. One alert per domain per 6 hours, memory only, nothing written to disk. The app shows the alerts, safety advice, and a standing line that no alert does not mean no stalkerware (the list is incomplete; spyware with root can avoid Guardian). It cannot tell which app made the lookup. `SpywareDbTest` (8 groups, including the real list and a check that no shared hosting platform such as firebaseio.com is listed on its own) passes; four mutations each fail it. The emulator flow looks up a listed domain and checks the notification and the in-app alert. Not tested on a real phone. |
| Encrypted DNS, core (G18 part 1) | Claude wrote this. `DotClient` speaks DNS over TLS (RFC 7858) to one resolver: length-framed messages over one reused connection, answer id must match the query, one reconnect on error, timeouts. It fails closed: when the resolver cannot be reached it returns nothing, and Guardian must not resend the query in clear text. `DotProviders` lists Quad9 (dns.quad9.net) and Cloudflare (one.one.one.one), from their official pages on 2026-11-01; Mullvad was left out because its public DNS ends on 2026-11-02. `policy_check.py` now allows public resolver addresses only in DotProviders.kt and forbids UDP or port 53 in the DoT client. `DotClientTest` (8 groups against a local fake resolver, including concurrency and a stale answer) passes; a mutation that drops the id check fails it. App wiring (protected socket, platform TLS with hostname check, choice in the UI, off by default) is part 2. |
| Encrypted DNS in the app (G18 part 2) | Claude wrote this. Choice under "Encrypted DNS": Off (default), Quad9 or Cloudflare; stored as the provider id only (`DnsSettingsStore`, held to that by `policy_check.py`). The DoT socket is protected from Guardian's own tunnel, uses the platform trust store and checks the hostname twice (TLS endpoint identification and after the handshake). If the provider cannot be reached, lookups fail and the screen says so; there is no fallback to unencrypted DNS. Emulator flow step 4g: Quad9 answers a new name and the status reads connected. Not tested on a real phone. |
