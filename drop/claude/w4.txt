任务 W4(网站):工具页上的「本页网络请求」面板——把「本地处理」变成可以自己核对的证据。

背景:D2(文件清理工具的新图标)我已按你的稿子合并,桌面和 390px 截图都通过。

需求:在「文本脱敏」和「文件元数据清理」两个工具页上,结果区下方加一个默认折叠的面板,如实列出这个页面加载后浏览器发出的全部请求,让用户在选文件/粘贴文本前后自己对比。

硬性规则:
- 只能用真实数据:performance.getEntriesByType('resource') 加 PerformanceObserver({type:'resource', buffered:true})。不写任何固定数字,不写「0 个外发请求」这类宣称。
- CSP 不变:script-src 'self'(不能有内联脚本、内联 style 属性、事件属性 onclick=)。新脚本 public/tools/assets/net-log.js,用 <script src=... defer>。不加依赖,不用 CDN。
- 页面由 toolshell 按顶层 <section> 切片,面板内部不能再嵌套 <section>,用 <div>/<details>。
- 中文用户看得懂,但这两页目前是英文页,面板文案用英文;另给出对应中文文案放在回答末尾备用。
- 设计遵循现有 tool-widgets.css 的变量和间距(你在 D1 用过的),新 CSS 只追加,类名前缀 .netlog-。

面板内容:
1. <details class="netlog"> 标题行:"Network requests from this page: N"(N 实时更新)。
2. 展开后是一个表:时间(相对页面加载,秒,1 位小数)、类型(initiatorType)、地址(同源只显示路径;跨域显示完整 origin+路径,并加一个「external」标记)、大小(transferSize,0 时显示 "cached" 或 "—",说明原因写在 title 里)。
3. 用户操作分界线:在用户第一次选文件(input change)或第一次点「Redact」时,往表里插一条分隔行 "You picked a file / You ran the redactor"。之后的请求行加粗。这样用户能看出操作后有没有新请求(文件清理页第一次选文件时会加载同源的 WASM 引擎,这是正常的,在说明里写明)。
   - 用自定义事件解耦:net-log.js 监听 document 上的 'netlog:mark' 事件(detail.label);我会在 mr-app.js 和 redact-app.js 里各加一行 dispatchEvent。你也给出这两行。
4. 面板底部固定说明(诚实边界):
   "This list comes from your browser's Resource Timing API. It shows what this page loaded or sent with fetch, XHR and beacons. It cannot show WebSocket or WebRTC traffic, browser extensions, or requests the browser hides from pages, so it is evidence, not proof. The stronger guarantee is the page's Content-Security-Policy, which you can read in your browser's developer tools (Network tab, response headers), and the source code on GitHub."
   GitHub 链接用 https://github.com/Paul30028/secureinchat 。
5. 无 PerformanceObserver 的浏览器:面板显示 "Your browser does not expose request timing to pages." 不报错。
6. 可访问性:表格有 <caption> 或 aria-label;分隔行用 <th scope="row" colspan>;颜色以外还有文字标记(external)。

输出:
- public/tools/assets/net-log.js 完整内容(IIFE,不污染全局,只读 DOM 中 #netlog 容器)
- 两个 HTML 页面里要插入的标记片段,并说明插在哪一行之后(以下面给出的源文件为准)
- tool-widgets.css 追加的 CSS
- mr-app.js 和 redact-app.js 各要加的一行
- 中文文案备用
不写进度百分比。

    <h2 id="what-h">What it does</h2>
    <p>Paste text and the tool replaces emails, phone numbers, IP and MAC addresses, card numbers, IBANs (checked with the standard checksum), API keys, tokens, passwords inside URLs and private keys with labelled placeholders such as <span class="mono">[EMAIL_1]</span>. The same value always gets the same placeholder, so a log stays readable after redaction. This is useful before you paste a log, a config or an email into a bug report, a forum or an AI assistant.</p>
    <h2>What it does not do</h2>
    <p>It finds patterns, not meaning. Names, street addresses, company names and anything written in an unusual format are not detected. Add names you know about under "Names and other words to hide" and they are replaced with [NAME_1], [NAME_2] and so on; the tool does not discover names by itself. Always read the result before you share it. A card number is only replaced if it passes the standard checksum, so a made-up number may be left alone.</p>
    <h2>How your text is handled</h2>
    <p>The text is processed in this page. It is not uploaded, logged or stored, and the page loads no analytics. Your browser or an extension may still keep what you type, so use a private window for sensitive material. Related: <a href="/tools/photo-metadata-remover/">remove metadata from a photo</a>.</p>

    <h2 id="what-h">What it removes</h2>
    <p>Most files carry a block of hidden data next to the content you see. A phone photo can hold the exact coordinates where you stood, the time and the device model. A Word or PDF file can hold the author, the company, the software that wrote it, and the times it was created and last edited. A video or an audio file can hold the device, the software and the date. Whoever receives the original file can read all of it with free software.</p>
    <p>This page lists what the file holds, then makes a copy without it. The original file is not changed. The listing, the cleaning and the second scan all happen in your browser, so the file never leaves your device.</p>
    <p>The orientation tag of a photo is kept on purpose, so a photo does not come out turned. For HEIC photos and MP4 video the library clears the metadata bytes where they sit instead of rebuilding the file, so the cleaned copy has the same size as the original. That is normal: the data is gone, the empty space stays.</p>
    <h2>What it does not do</h2>
    <p>It does not change what the file shows. The text of a document and the faces, signs and landmarks in a photo are still there. Hidden data is only one way a file gives something away, so read the content as well before you share it.</p>
    <p>Old Office formats (.doc, .xls, .ppt) are not supported. Open the file and save it as .docx, .xlsx or .pptx, then clean the new file. Formats that are not in the list are refused before they are read.</p>
    <p>It handles one file at a time, up to 200 MB, and does not unpack archives. A file is only cleaned if it can be read: a damaged file is reported, not repaired.</p>
    <p>After cleaning, the page scans the new file again and shows what is left. Some values belong to the file structure and cannot be removed without breaking the file; those are listed instead of hidden. A short list is a check, not a promise that the file is safe.</p>

No file is uploaded, nothing is stored, and the page loads no analytics.</p>

    <h2 id="faq-h">Frequently asked questions</h2>
    <h3>Is my file uploaded?</h3>
    <p>No. The file is read, cleaned and scanned again inside this page with WebAssembly. There is no upload and the page stores nothing.</p>
    <h3>Which formats work?</h3>
    <p>JPEG, PNG, WebP, AVIF, GIF, HEIC, HEIF, TIFF, SVG, MP4, MOV, MP3, FLAC, WAV, OGG, PDF, DOCX, XLSX, PPTX, ODT, ODS, ODP and EPUB. Old Office files (.doc, .xls, .ppt) are not supported: save them as .docx, .xlsx or .pptx first. Anything else is refused before it is read.</p>
    <h3>Why is my HEIC or video the same size after cleaning?</h3>
    <p>For HEIC and MP4 the library clears the metadata bytes where they are instead of rebuilding the file, so the size stays the same. The data is gone; the empty space remains. This is normal.</p>
    <h3>Will the content change?</h3>
    <p>No. Only hidden metadata is removed. The text of a document, and the faces and street signs in a photo, are still there. The orientation tag is kept, so a photo does not turn.</p>
    <h3>Why does the second scan still show something?</h3>
    <p>A few values are part of the file structure and cannot be removed without breaking the file. The page lists them after cleaning instead of hiding them. If that list matters to you, do not share the file.</p>
    <h3>Which library does this use?</h3>
    <p>The open source metadata-remover by iAnonymous3000, used under the MIT licence. The licence text is at /tools/assets/mr/LICENSE.txt and the source is at github.com/iAnonymous3000/metadata-remover.</p>
