## 做了什么

**原生 `KeystorePlugin.java`**(注册名 `HardwareKeystore`,已在 MainActivity 注册，无新依赖)
- Android Keystore 里的 AES-256-GCM 密钥，不可导出;API 28+ 先试 StrongBox，失败回退 TEE。
- 实际级别从 KeyInfo 读(API 31+ 用 securityLevel;31 以下 StrongBox 和 TEE 都报 tee——只会少说不会多说)。
- **不绑定用户认证**、不随新录指纹失效(M1 决定)。IV 由 Keystore 随机生成。错误码 KEY_MISSING / KEY_INVALIDATED / UNWRAP_FAILED / KEYSTORE_ERROR。原始字节用完清零，不写 logcat。

**JS 侧**
- `secure-storage/masterKeyProvider.ts`:32 字节随机主密钥 → 硬件密钥包裹 → **落盘前先解一次核对** → 导入为不可导出 CryptoKey → 原始字节清零。落盘的只有包裹后的字节(Uint8Array，老 WebView 能存)。解不开时抛 `MasterKeyUnavailableError`,**绝不悄悄换新密钥**。Web 端、Keystore 不可用的设备保持原做法，标为 `webview` 级别。
- `EncryptedKeyValueStore`:可带旧主密钥(读先新后旧，写用新);`migrateLegacy()` 在写锁下逐条改写，应用在「迁移读旧值 → 写回」之间的写入不会被覆盖;整轮成功后才删旧密钥。中途断电：每条要么旧密钥要么新密钥，都能读，下次启动继续。
- `deviceIdentity.ts`:接上 provider，启动后后台迁移;`resetLocalEncryptedData()`;`PLAINTEXT_SETTING_KEYS`(应用锁、昵称等明文设置，重置时保留)。
- 界面：「本机数据无法解密」页(在应用锁之后)：说明原因(硬件密钥丢失/作废/其他);「重试」;「清空本机数据，从备份恢复」要二次确认，清空后直接进备份页。「我的」页加「本机数据保护」一栏，写明级别和**不防什么**。
- README 和手册(4.1、第 7 节)写清边界：防拷走数据目录离线解密;不防已解锁设备上以本应用身份的提取;应用锁 PIN 不参与加密;网页版没有硬件保护;设备签名密钥未硬件化。

**测试发现并修掉的真问题**:读字节记录原来用 `instanceof Uint8Array`,跨 realm 时为 false,记录会被当成「没有」→ 生成新主密钥覆盖旧的 → 数据永久解不开。现在用 `ArrayBuffer.isView`,而且「有记录但认不出来」直接报错，不当成没有。
