# 包 1：设备安全优先（Paul 2026-11-04 16:48 批准开工）

依据：`docs/design/PRIVACY_FOR_EVERYONE.md`（分支 `docs/privacy-for-everyone`）和项目文档 `docs/original-design-ideas-2026-11-04.md`。
威胁：手机在拘留、过境、检查时被拿走并做取证提取（Amnesty 2024-12 塞尔维亚报告：Cellebrite 解锁后装间谍软件）。
原则：手机里**本来就没有**，比藏起来更安全。不做伪装界面、不做假密码打开假数据。

## 代码现状（2026-11-04 审查 `feature/chat` b074fe0）

- 本地数据都在 `EncryptedKeyValueStore`（IndexedDB `secureinchat-storage`），用设备主密钥加密。
- 每个群的数据分散在这些键里：
  - `groups:joined`（群列表，含原始密钥材料）
  - `messages:<gid>`
  - `devices:<gid>`
  - `group:<gid>:epoch:<n>`（每个 epoch 的原始群密钥）
  - `admin-key:<gid>`（管理员恢复码，等同管理员身份）
- **发现的问题（P1a 修复）**：`handleLeaveGroup` 只删除群列表、消息、设备名单，**没删** `group:<gid>:epoch:*` 和 `admin-key:<gid>`。退群后手机里仍留着这个群所有 epoch 的密钥，如果是管理员，还留着管理员身份。
- 已经有「全部清除」：应用锁输错次数用尽时，删掉 4 个 IndexedDB 数据库（含主密钥，等于把全部数据做了加密粉碎）。但没有一个用户可以主动触发的入口。
- 设备身份是全局的：一台手机只有一个 `deviceId`，用一把签名密钥连接所有群，所以中继能把同一台手机在不同群里的活动联系起来。

## 边界（写进界面和 README）

- **IndexedDB 删除是逻辑删除**：数据库文件的空闲页里可能残留密文，但它们由设备主密钥加密。「全部清除」会删掉主密钥，所以残留密文不可解；单个群删除后，主密钥还在。后续 P1e 改为**每群独立数据密钥**，删群即删密钥（加密粉碎），彻底解决这个问题。
- **P1d 只去掉显式标识**：中继仍能看到同一个 IP 在同一时间连接多个群。按时间和 IP 做关联，需要网络层手段才能防住，我们不承诺。
- 已经导出到手机文件里的备份（C9）不归 App 管，界面上要提醒用户自己删除。
- 已经被装了间谍软件的手机，在上面做什么都不可信。P1c 的意义是「不要再用这台手机」，不是「清除后就安全了」。
