# 威胁模型 v0.1

## 1. 信任边界

| 角色 | 信任程度 | 说明 |
|---|---|---|
| 客户端设备 | 高（用户自己的设备） | 私钥只存 Android Keystore，业务代码不可读取原始私钥 |
| 中继服务器 | 不可信（零知识） | 只能看到密文、路由元数据、时间戳；不得持有可解密内容的密钥 |
| 网络路径 | 不可信 | 假设存在被动监听和主动中间人 |
| 群组管理员（业务角色） | 半信任 | 能管理成员/邀请码，但不能获得解密聊天内容的能力 |
| 被移除的群成员 | 不可信 | 移除后必须无法解密后续消息（要求群 epoch 轮换） |

## 2. 资产

1. 消息明文（文本/语音/图片/文件内容）
2. 群共享密钥材料 / 设备私钥
3. 邀请码（一次性/限次使用凭证）
4. 元数据（谁在何时给谁发了多大的消息）——服务器不可避免地会看到一部分，需最小化

## 3. 主要威胁与对应设计

| 威胁 | 对应机制 |
|---|---|
| 服务器被攻破，读取聊天内容 | 服务器只存密文 + IV/nonce，密钥不经过服务器 |
| 设备丢失，本地数据被读取 | 私钥存 Android Keystore（硬件支持时用 StrongBox），应用锁 + 生物识别，禁止 localStorage 存敏感材料 |
| 成员被移除后仍能解密新消息 | 移除触发群 epoch 轮换，新 epoch 密钥不下发给被移除成员 |
| 消息重放攻击 | 每条消息带客户端消息 ID + 发送序号 + epoch，接收端去重并校验单调性 |
| 中间人在邀请环节篡改身份 | 安全码验证页（对比双方设备指纹），密钥变化时强提示重新验证 |
| 文件被中继篡改或截断 | 分片级 AEAD + 文件级完整性校验，客户端校验后才提示"完整性已验证" |
| 管理员越权读取消息 | 管理员权限只覆盖公告/成员/邀请码/中继健康度，协议层不给管理员角色额外密钥 |
| 邀请码被爆破或长期有效被滥用 | 邀请码限次 + 限时，管理员可轮换服务器侧入群码而不影响已建立会话的群密钥 |

## 4. 附录 A：旧仓库（secure-invite-chat）已知原型缺陷——不得继承

以下是对旧仓库 README/ROADMAP 的如实转述，作为"反面清单"，本仓库的实现和测试都要能
证明自己没有重复这些问题：

- 敏感材料仍有部分存放在 WebView `localStorage`。
- 群组共享密钥缺少完整前向保密；密钥一旦泄露，历史密文可被解密。
- 成员移除后的密钥轮换未完全达到正式安全标准。
- MLS 是目标架构，当前并未真正实现。
- 文件经 WebSocket 传输，单文件建议 ≤4MB，未正式分片。
- 音视频通话未完整实现。
- 公告签名验证未完整实现。
- 正式发布签名和供应链验证未完成。

## 5. 尚未达到的目标（诚实披露，不得包装成已完成）

- 群组消息的前向保密与后向保密（MLS 目标）。
- 生产级 TURN/SFU 部署（本仓库只做客户端接口，不代管基础设施）。
- 正式签名与供应链完整性（SBOM 已排入 CI 计划，签名密钥由你自行持有）。
