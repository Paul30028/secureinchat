What each result means

Public IP
The address every website you visit sees. With a VPN on, it should belong to your VPN provider's network, not your internet provider. The city and network name come from IP geolocation data, which can be off by a city or more.
WebRTC
WebRTC lets browsers connect directly for calls. To do that it asks a STUN server for your public address, and any page can read the answer without a permission prompt. If that address differs from your public IP, WebRTC is going around your VPN.
IPv6
Some VPNs tunnel only IPv4. If your device also has IPv6, sites that support it can reach you over IPv6, outside the tunnel, with an address that identifies your provider.
DNS
DNS turns names into addresses. A DNS leak means your lookups go to your internet provider's resolver instead of your VPN's, so your provider can see which sites you visit.
Time zone
Your browser tells every page its time zone. If it says Asia/Shanghai while your IP sits in Frankfurt, fraud checks read that as a sign you are hiding your location. It is a signal, not proof.
Request headers
Headers such as Via and X-Forwarded-For can announce a proxy. Your language header can also disagree with your IP's country, a weak signal that some fraud checks use.

Frequently asked questions

Does a WebRTC result mean my VPN is broken?

Only if the public WebRTC address differs from the IP that websites see. A local address ending in .local, or an address that matches your public IP, is normal.

Why does the test ask whether I'm using a VPN?

The test cannot tell. A home IP address is normal without a VPN and a problem with one. The checkbox decides whether results are judged as pass or fail, or only shown.

Does private browsing stop these leaks?

No. Private windows clear history and cookies, but WebRTC, IPv6, DNS and the time zone behave the same way.

Should I turn WebRTC off?

Only if you cannot limit it another way. Turning it off breaks browser video calls and some web apps. Limiting WebRTC to the default public interface, or blocking non-proxied UDP, usually closes the leak and keeps calls working.

How does the DNS check work?

Your browser looks up a few random names under a domain we run. The DNS server for that domain records which resolver asked, and the page reads that list back and looks up whose network each resolver is on. A resolver on your exit network passes. A resolver that also answered when you ran the test without a VPN fails. A public resolver such as Google or Cloudflare is shown as information, because the test cannot tell who chose it.

Why does IPv6 matter if my VPN works?

Many VPNs tunnel only IPv4. If your network also has IPv6, sites that support it connect to you over IPv6, outside the tunnel.

How accurate are the location and network name?

They come from IP geolocation data. The city is often off, sometimes by a lot. The network name is usually right. The hosting-or-ISP judgment is a heuristic based on the network name and can be wrong for residential VPN exits and corporate VPNs.

Do you store my IP address or results?

The page's code stores nothing. Results are built in your browser and disappear when you close the tab. Cloudflare, which hosts the site, processes every request it serves, as it does for any site. The lookups listed under How the test works leave your browser.

How the test works

Everything is judged in your browser. These requests leave it when you press Run test:

This site, /tools/api/whoami
Returns the address Cloudflare saw, its network, an approximate location and a few request headers. The code writes nothing to disk.
api4.ipify.org and api6.ipify.org
Return your IPv4 and IPv6 address separately. If your network has no IPv6, the IPv6 request fails, and the test reads that as no IPv6.
ipwho.is
Looks up the network of your second address when the test finds one, and the network of each DNS resolver.
Random names under lk.secureinchat.com
The DNS check asks your system to look up six names that exist only for this run. Our DNS server answers them and notes the address of the resolver that asked. It keeps that in memory for ten minutes and writes no log. It also keeps a daily count of tests, a number with no addresses in it. A per-resolver counter that limits abuse stays in memory for up to an hour.
dnsapi.secureinchat.com
Returns the resolver addresses recorded for this run, and only this run. Like any server, it sees your IP address when your browser asks.
stun.cloudflare.com
The WebRTC check asks this STUN server for your public address, the same way a video call would.

The page sets no cookies, loads no analytics and serves its fonts from this site. Pass and fail judgments depend on the VPN checkbox. The DNS check compares with an earlier run in the same tab, which it keeps in memory only. Updated October 20, 2026.
