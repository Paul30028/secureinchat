How a WebRTC leak happens

WebRTC is the browser feature behind video calls. To set up a call, a page asks the browser for its candidate addresses, and the browser answers by contacting a STUN server and listing what it finds. A VPN usually routes web traffic through its tunnel, but that STUN request is UDP, and on some setups it leaves through your normal connection. The result is a public address that differs from the one websites see.

This test makes the same request any page could make. It compares each public address with the one the site's own lookup returned. A match is fine. A different address, with the VPN box ticked, is reported as a leak.

How to close a leak

  • Firefox: set media.peerconnection.enabled to false in about:config. Browser video calls stop working.
  • Chrome and Edge: install an extension such as Google's WebRTC Network Limiter and choose the default public interface only.
  • Brave: in Privacy and security, set WebRTC IP handling policy to disable non-proxied UDP.
  • Any browser: use a VPN client with a kill switch that blocks all traffic outside the tunnel, UDP included. Run this test again afterwards.

Frequently asked questions

What is a WebRTC leak?

WebRTC lets a web page ask your browser for the network addresses it would use for a call. Those addresses can include one that is not the address websites see through your VPN or proxy, and a page can read them without a permission prompt.

Does a local address like 192.168.x.x count as a leak?

It is not a route to you from the internet, but it is a fingerprinting detail. Current Chrome, Firefox, Edge and Safari normally replace it with a random .local name.

Which browsers can leak through WebRTC?

Any browser with WebRTC can. Whether a public address leaks depends on the browser, its settings and how your VPN routes UDP traffic.

How do I fix a WebRTC leak in Firefox?

Open about:config, search for media.peerconnection.enabled and set it to false. This turns WebRTC off, so browser video calls stop working.

How do I fix it in Chrome or Edge?

These browsers have no built-in switch. Google's WebRTC Network Limiter extension can set the policy to use only the default public interface, which keeps calls working. Brave has the setting under Privacy and security as WebRTC IP handling policy.

Does a VPN kill switch stop WebRTC leaks?

Often, if it blocks all traffic outside the tunnel, including UDP. A kill switch that only reacts to dropped connections may not.

Does this page store my address?

The page's code stores nothing and sets no cookies. The lookups it makes are listed on the IP leak test page under How the test works.
