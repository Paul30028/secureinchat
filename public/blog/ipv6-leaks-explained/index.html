IPv6 leaks explained: why a VPN can show one address and expose another

Why a connection with both IPv4 and IPv6 can leak around a VPN that tunnels only IPv4, how the IPv6 leak test decides, and the fixes in order of preference.

By Paul2026-10-20

Many people check one number, the IP address a website shows, and stop when it matches their VPN. That number can be an IPv4 address while a second, IPv6 address goes out another way. The IPv6 leak test checks for exactly that.

Two addresses, two routes

A device on a modern home or mobile network usually has an IPv4 address and an IPv6 address. When a website supports both, the system prefers IPv6. A VPN that creates a tunnel only for IPv4 leaves the IPv6 route untouched, so connections to IPv6-capable sites bypass it.

How the test decides

The page asks one lookup service for your IPv4 address and another for your IPv6 address. It then looks up which network owns each. If both belong to the same network, both routes share an exit. If they belong to different networks while you say you are using a VPN, IPv6 is leaving outside it.

If the lookup that names the network fails, the result is a warning rather than a pass, because the test has not shown the addresses are on the same network.

Caveats

  • Network names come from IP data. Two networks run by one company can have different names, and records can be out of date, so treat a mismatch as a reason to look closer.
  • No IPv6 address in the result means your network did not reach the internet over IPv6 during the test. For leak purposes that is a pass, because there is nothing to leak.
  • The result is for one browser, one network and one moment.

Fixes, in order of preference

  1. Turn on IPv6 leak protection in your VPN client, or use a VPN that tunnels IPv6.
  2. Enable the client's kill switch so nothing leaves outside the tunnel.
  3. As a last resort, disable IPv6 on your network adapter or router. This removes a working connection, so undo it when you stop using the VPN.

Run the test again after each change. Then check WebRTC, which is a separate route around a tunnel.
