WebRTC leaks explained: what a page can read and how to read your result

What a WebRTC leak is, why a VPN can miss it, how to tell a real leak from a harmless local address, and the browser-by-browser options for closing it.

By Paul2026-10-20

WebRTC is the browser feature behind video calls and some file-sharing sites. It is also the most common reason a VPN user sees a second address in a leak test. This post explains what the WebRTC leak test reports and what to do with each result.

What actually happens

To connect two browsers directly, each side needs to know which addresses it can be reached on. The browser gathers these candidates, including the address a STUN server sees. Any web page can start this process through JavaScript, and no permission prompt appears for the address lookup itself.

A VPN client usually routes ordinary web traffic through its tunnel. If the STUN request, which is UDP, leaves through your normal connection instead, the page learns an address that is not your VPN exit.

Reading the result

  • The address matches your public IP. Nothing leaks beyond what every website already sees.
  • A different public address, with the VPN box ticked. This is a leak. A page can read your real network without asking.
  • A name ending in .local. The browser hid your local address behind a random name. This is the intended behaviour.
  • A raw local address such as 192.168.x.x. It is not reachable from the internet, but it is one more detail a tracker can use to tell you apart from other visitors.
  • No addresses. Either WebRTC is off, or UDP to the STUN server is blocked. It means the question could not be asked, not that you are certain to be safe.

Closing a leak

The options differ by browser. Firefox lets you turn WebRTC off in about:config by setting media.peerconnection.enabled to false, at the cost of browser video calls. Chrome and Edge have no built-in switch, but an extension can restrict WebRTC to the default public interface. Brave has a WebRTC IP handling policy in its privacy settings. A VPN client with a kill switch that blocks all traffic outside the tunnel, UDP included, can close the leak for every browser at once.

After any change, run the test again. The result is the only proof that matters, because settings and extensions change between versions.

What this test cannot tell you

It runs from one browser on one network at one moment. A different browser, or the same device on a different network, can behave differently. It does not test DNS. The full IP leak test does, using a DNS server we run. For the rest of the checks, use the full IP leak test, and read how it works for what each check can and cannot see.
