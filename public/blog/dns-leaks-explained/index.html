DNS leaks explained: what they are and how to read a DNS leak test

What a DNS leak is, why a VPN can still send lookups to your internet provider, how our DNS check reaches its verdict, and what to do about each result.

By Paul2026-10-20

Every time you open a site, your device first asks a DNS resolver to turn the name into an address. That resolver sees which sites you visit even if everything after it is encrypted. A DNS leak is when those questions go to a resolver you did not mean to use, usually your internet provider's, while you think a VPN is covering you. Our IP leak test checks for it.

How the check works

The page asks your system to look up six random names under a domain we run. We run the DNS server for that domain, so we see which resolver asks for them, and only that. The page reads that list back and looks up whose network each resolver is on. The names are unique to each run, so nothing is answered from a cache. The resolver address is kept in memory for ten minutes and is not logged. A small counter per resolver, used only to limit abuse of the usage count, stays in memory for up to an hour.

Reading the result

  • Pass: every resolver is on the same network as your exit address, so lookups are answered inside your VPN or proxy network.
  • Fail: a resolver that answered when you ran the test without a VPN also answers with it on. For this the page remembers the first run in your tab, in memory only.
  • Information: a well-known public resolver, such as Google or Cloudflare, answered. That is fine if you or your VPN chose it. The test cannot tell who chose it.
  • Warning: a resolver on a different network answered, no lookups reached us, or the network of a resolver could not be identified. A different network is normal if it belongs to your VPN provider.

Why it is not a plain pass or fail

The test cannot know who your internet provider is. Judging a resolver as a leak only because it sits on another network than your exit would flag many VPNs that use their own resolvers elsewhere. So the clear failure case needs a comparison: the same resolver with and without the VPN.

Browsers that use DNS over HTTPS

Some browsers send lookups to a provider such as Cloudflare or Google over HTTPS, bypassing the system resolver. That is not a bug in the test. The provider's resolver is what is actually answering, and it is what you will see.

Fixing a leak

  1. Turn on DNS leak protection in your VPN client and do not override the DNS servers it sets.
  2. Use the kill switch so lookups cannot leave outside the tunnel when it drops.
  3. Check the browser's secure DNS setting, which can send lookups around the VPN to a provider you did not choose.

Run the test again after each change, with the VPN box unticked first and ticked second. For the other routes around a tunnel, see WebRTC and IPv6.
