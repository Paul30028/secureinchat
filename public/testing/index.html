How we test

Every release of this site runs 20 groups of automated tests before it goes live. This page says what they check, and what they do not.

Last updated: 2026-10-23

On this page

  • The website and tools
  • The Android app
  • What these tests do not prove

The website and tools

  • Tool pages are opened in a real Chromium browser, served with the same Content Security Policy headers the live site uses.
  • For tools that say they run on your device (photo metadata, text redaction, link checker, fingerprint test, account and phone checklists), the tests record every network request and fail if anything leaves the page.
  • Tools that use outside lookups are tested with those services mocked, so the tests check how results are judged without sending real addresses anywhere.
  • The photo metadata remover is tested with JPEG, PNG and WebP files, rotated photos, photos with no metadata, a 35-megapixel photo, corrupt files and formats it does not support.
  • The logic of the password, redaction, link and account tools has its own unit tests.
  • Every internal link on every page must point to a page that exists, and the main pages are checked for missing files, console and CSP errors, and horizontal overflow on a phone-sized screen.
  • The Chinese pages are checked for rules we set for them, such as which tools they link to.

The Android app

Permission Checkup is built on GitHub Actions on every change:

  • Core logic tests in plain Kotlin.
  • A policy check that the app requests no INTERNET permission and has no third-party dependencies, plus an inspection of the built APK's permissions.
  • Android lint.
  • Launch tests on Android 10 and Android 14 emulators, and a flow test that revokes a permission, records it, restarts the app and restores it.

What these tests do not prove

  • They are our own tests. Nothing on this site has had an independent security audit.
  • The website tests use Chromium. Firefox and Safari are checked by hand at most.
  • The Android app has not yet been tested on a physical phone.
  • A passing test means the code does what we wrote down. It does not prove the design is right.

The status labels on each page say what was tested and what was only documented. See what each tool sends, and report a problem if you find one.
